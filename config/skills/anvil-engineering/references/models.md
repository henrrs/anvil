# Models and local interface

The helper accepts one JSON document with separate `requirements`, `architecture`, and `work` objects. It stores them in one checksummed atomic generation so an interruption cannot publish only one updated model. It adds execution metadata; do not edit private state files as a shortcut around transitions.

`requirements` contains `objective`, `items`, and optional `constraints`, `risks`, `deferred_scope`. Each item has a stable `id`, `statement`, `type`, `priority` (`required`/`optional`), and `source` with `document`, `section`, and optional inclusive `lines`. Initial status is PENDING; DEFERRED/NOT_APPLICABLE require `disposition_reason`. Required deferral still blocks completion. Scope removal needs the user's actual authorization; a convenient replan is not authorization. Derived statuses distinguish PENDING, IN_PROGRESS, IMPLEMENTED, VERIFIED and BLOCKED. `implemented_by` and `verified_by` trace meaningful implementation/evidence.

`architecture` contains concise `principles`, `boundaries` (`id`, `owns`, `must_not_know`, optional `depends_on`), `decisions` (`id`, `context`, `decision`, `consequences`, optional `paths`, status VALID/AMENDED/SUPERSEDED), `invariants`, and `unknowns` (`id`, `question`, `blocking`, status OPEN/RESOLVED with evidence). Decisions use the project's existing ADRs where useful; do not create ADRs for trivial edits. Changes invalidate affected evidence; amend or supersede a decision explicitly.

Each invariant has `id`, `statement`, `kind`, `paths`. Kinds are `forbidden_imports` (Python AST module prefixes in `forbidden`), `forbidden_text` (literal strings in `forbidden`), `required_files`, or `semantic`. Scope is explicit and bounded. Mechanical checks do not prove responsibility ownership, retry correctness or design quality. Record those through a semantic review with observer and evidence rationale; report its judgment separately from observed execution.

`work` contains coherent `milestones` and executable `tasks`, plus project `done_when`. Milestones have `id`, `title`, optional `depends_on`, and `done_when`. Tasks have `id`, `title`, `milestone`, `requirement_ids`, optional `decision_ids`/`depends_on`, explicit relevant file `paths`, `checks`, and `done_when`. Check IDs are globally unique. A command check is `{ "id": "C1", "kind": "command", "argv": ["python3", "-m", "unittest"], "timeout": 120 }`. A semantic check is `{ "id": "C2", "kind": "review", "statement": "Retry ownership matches the architecture" }`.

At each level, `done_when` is a nonempty list such as `[{"statement":"Recovery behavior verified", "check_ids":["C1","C2"]}]`. Every referenced check must exist. A milestone also requires all its tasks VERIFIED; a project also requires required coverage, completed milestones, successful invariants and resolved blocking unknowns. DAG cycles and missing dependencies are errors. Keep milestones aligned with responsibility or vertical behavior, rather than separate file/test/document phases.

Use `analyze --spec SPEC` for bounded source inventory, then perform semantic normalization. `init --repository REPO --id TASK --spec SPEC --models MODELS.json` creates explicit state. All mutations after init require the last observed `--revision N`; a concurrent update requires reloading. `status`, `resume`, `list`, `assess` and `analyze` are read-only. JSON mode is `--format json`; text mode emphasizes status, impact and next action. An absent state is valid and never means Anvil is corrupted.

Preserve conflicting source claims and unresolved requirement interpretations as explicit risks/unknowns with provenance. Do not silently choose a convenient interpretation, collapse architecture into a task list, or copy a physical plan into progress state.

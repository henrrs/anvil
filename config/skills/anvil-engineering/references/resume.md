# Resume and stale evidence

After interruption or compaction, run `resume --repository REPO --id TASK --format json`. It reconstructs objective, architecture, relevant decisions/requirements, milestone, task, blockers, verified work and next action from local state. It does not execute code, repeat a command, modify sources or persist memory. Read only the named current-unit sources afterward; the entire specification/history need not return to context.

An ACTIVE task may have partial external effects. Inspect them first, including commit/checkpoint/resource identity where relevant. Use `reconcile --task T --outcome PENDING|IMPLEMENTED|BLOCKED --reason 'inspection evidence'` only after determining what actually happened. Completed tasks are not replayed. Uncertain destructive operations remain blocked until their effect can be established safely; a state file cannot supply idempotency for an external API.

Repository root, branch/HEAD, named file hashes and specification hash anchor evidence. `WORK_STATE_STALE` identifies changed paths/anchors. `revalidate --reason 'observed changes and inspection'` invalidates affected checks/dependent units while preserving unaffected work. It acknowledges harmless Git changes only after inspection. Changed specification content requires semantic normalization and `replan`; do not merely accept a new hash. Decision `paths` identify assumptions needing renewed architecture review.

State is private, checksummed JSON under the Anvil XDG state root, separate from memory, knowledge, sources and lifecycle transactions. Writes use a lock, expected revision, fsync and atomic replacement; the last valid prior generation is retained. Corrupt state is never silently replaced with an older success. `recover --revision N` uses the explicitly inspected previous generation's revision, only when current state is invalid/missing; all recovered verification is invalidated and revalidation is required. An absent/corrupt task does not corrupt the installed Anvil profile. Inspect and resume it independently.

Completed state is retained for audit/resume; `archive --reason ...` makes a task read-only. Retention/deletion is explicit user work, never implicit memory promotion. State absence is valid, upgrades do not migrate or delete task data, and rollback may leave a newer task schema unreadable to an older helper. Restore the newer helper or inspect/export JSON; never downgrade state silently. `ANVIL_ENGINEERING=off` is an evaluation/rollback activation override; direct tasks remain valid without a store.

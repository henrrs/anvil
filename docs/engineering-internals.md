# Engineering core contracts

The entrypoint `scripts/engineering.py` delegates to a stdlib package. `specification.py` owns cheap activation signals and bounded spec inventory. `contracts.py` validates separate Requirements, Architecture and Work models and their combined dependency graph. `repository.py` observes only named evidence. `store.py` owns private generations, integrity, locking and atomic writes. `engine.py` owns transitions, requirement traceability, verification invalidation and completion. `invariants.py` evaluates declared mechanical boundaries. `verification.py` executes explicit checks. `context.py` reconstructs bounded continuation state; `cli.py` presents it.

The three models share an atomic envelope, not their responsibilities. The schema is version 1. Requirements have source provenance, priority and distinct PENDING/IN_PROGRESS/IMPLEMENTED/VERIFIED/BLOCKED/DEFERRED/NOT_APPLICABLE states. Work owns tasks, milestone dependencies and definitions of done. Architecture owns principles, boundaries, invariants, concise ADR references/decisions and unresolved assumptions. See the installed skill's [model contract](../config/skills/anvil-engineering/references/models.md) for fields and check examples.

Command checks are declared argv arrays. They run explicitly, without implicit shell interpolation, bounded to 1–600 seconds and 2 MiB of output. Persisted evidence contains result, command-definition hash, relevant file hashes, output digest, timing and confidence, not raw logs. Semantic reviews record observer, scoped files, judgment and concise evidence rationale; their supported status is never disguised as an observed test. Requirements cannot import VERIFIED status; they derive it from linked work and current evidence. A changed check definition cannot reuse an old PASS.

Milestone completion requires verified tasks, its check-backed criteria and any declared `invariant_ids`. Project completion additionally requires required requirements verified/not-applicable with explicit rationale, all milestones complete, all invariants PASS, resolved blocking unknowns and reviewed invalidated decisions. Required deferral blocks completion. A replan that removes/downgrades required scope needs `--scope-authorization` referring to actual user authorization. The core cannot adjudicate whether a model's semantic judgment is true; the protocol requires honest evidence and user boundaries.

State paths use the canonical repository identity and explicit task ID under the Anvil XDG state root. Reads do not create directories. Writes reject symlink traversal, apply 0700 directories/0600 files, hold an advisory lock, compare expected revision, fsync and atomically replace a checksummed envelope. Verification holds that lock too, so two stale callers cannot run the same registered check before a conflict is noticed. A prior valid generation is retained. A corrupt current generation is never silently replaced; explicit recovery invalidates evidence and demands revalidation. Interrupted temporary files are ignored, not treated as valid state.

Repository observations contain branch/HEAD, named file hashes and spec identity/hash. No repository-wide startup scan or credential/environment dump occurs. Resume reports drift and invalidates affected evidence in its read-only view. Explicit revalidation persists invalidation through task and milestone dependencies, preserving unaffected completion. Specification changes require semantic replanning. Decision paths identify assumptions needing review. Active work is inspected and reconciled; no implementation or external mutation is scheduled automatically.

Errors use actionable categories such as SPECIFICATION_INVALID, REQUIREMENT_CONFLICT, BLOCKED_DEPENDENCY, WORK_STATE_STALE, WORK_STATE_CORRUPTED, VERIFICATION_FAILED, REPEATED_FAILED_ACTION and UNSAFE_PATH. Missing state is valid. Text output emphasizes impact and next action; `--format json` exposes structured state. Packets are limited to 24 KiB and select the current work unit; oversized models must be narrowed rather than silently truncated. Events retain concise outcomes/counters, not hidden reasoning; verification retains latest records and failures have a bounded history.

Recognition of common credential patterns and rejection of raw authentication/log/environment fields supplement the protocol's prohibition on storing secrets; they are not a universal data-loss-prevention classifier. Use non-secret command arguments and concise evidence. The core does not implement distributed execution, general workflow scheduling, external-effect idempotency, automatic spec extraction, automatic truth judgments or automatic durable-memory writes. `ANVIL_ENGINEERING=off` disables new activation for evaluation; existing state remains inspectable.

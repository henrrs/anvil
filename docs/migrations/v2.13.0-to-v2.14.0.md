# Anvil 2.13.0 to 2.14.0

Anvil 2.14 realigns the local analysis package and improves semantic candidates, repeated-entity cohorts, contribution analysis and evidence-linked claim checks. The migration adds no runtime feature, dependency, model, service, persistent state, memory schema, OpenCode profile setting, or public Make target.

Preview and upgrade Anvil while preserving the exact OpenCode runtime and local configuration:

```bash
git pull origin master
make test
make upgrade DRY_RUN=1
make upgrade
make capabilities
```

The helper remains in the managed OpenCode package tree. `profile` output now includes a bounded `semantic_context`; plans can pass that JSON to `execute --profile PATH` to reuse semantic inference. Execution verifies the source path, SHA-256, row count and profile completeness, then rereads the source for calculations and source-mutation checks. Do not treat candidate key/entity roles as confirmed business definitions.

The communication adapter moved from the analysis package to `scripts/communication/analysis_adapter.py`, and communication uses shared change/distribution calculations. These are repository-internal imports; no user configuration migration is required. Existing local plugins, MCP settings, provider settings, OpenCode data/state, Databricks state, and Anvil memory remain outside this change's ownership.

The supported same-major source window now covers eight prior minor releases, retaining the previously supported 2.6.x line. The 2.14 candidate remains **NOT READY** pending live-model analytical quality, claim fidelity, cost/latency and product-level regression evaluation. Offline tests do not establish those properties; see the [release report](../analytical-intelligence-report-v2.14.0.md).

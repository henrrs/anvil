# Anvil 2.2 to 2.3 migration

Anvil 2.3 removes the Databricks CLI as a hard dependency while retaining Anvil 2.2's execution capabilities and safety rules. OpenCode major versions do not change.

## Upgrade Anvil

```bash
git pull
make test
make upgrade DRY_RUN=1
make upgrade
make doctor
make capabilities
```

`make upgrade` preserves the current OpenCode major. Standard reforge/upgrade does not install Databricks tooling or contact Databricks. Runtime-major migration remains a separate explicit operation.

## Refresh Databricks providers

Existing Anvil 2.2 selected profile and workspace host are migrated when state is next saved. A valid CLI profile continues to work without reauthentication. To discover providers and deliberately allow user-local CLI/SDK setup, run:

```bash
make databricks-setup DRY_RUN=1
make databricks-setup
make doctor
make capabilities
```

The normal setup attempts the official CLI first and uses the SDK fallback in an isolated environment when needed. CLI installation does not use privilege elevation or modify shell startup files. If the CLI is present but absent from the current `PATH`, Anvil can use its verified absolute path and reports PATH visibility separately.

Provider metadata migration never rewrites `.databrickscfg`, removes a Databricks profile, logs out, or stores credentials. A previously saved invalid profile is not silently replaced.

## Rollback boundary

`make rollback` restores the managed OpenCode runtime/config/data/state snapshot. It does not uninstall the Databricks CLI, delete the Anvil-owned SDK virtual environment, alter auth profiles, or remove the VS Code extension. Existing Markdown memory remains separate and portable.

# Anvil 2.15.0 → 2.16.0 migration

Anvil 2.16.0 adds the default-installed Analytics Workspace and compatible OpenCode 1/2 tool adapters. The upgrade remains Anvil-only and preserves the exact validated OpenCode runtime.

The supported same-major source window extends to ten prior minor releases so previously supported Anvil 2.6.x installations remain upgradeable.

```bash
git pull
make test
make upgrade DRY_RUN=1
make upgrade
make doctor
make analytics-status
```

`make upgrade` installs the Analytics package and static UI into the managed global OpenCode config and synchronizes the Anvil-owned user service. It does not require an OpenCode major upgrade, install Databricks CLI/Python packages, authenticate to a workspace, or contact a model. The user service starts when systemd user mode is available; otherwise run `make analytics` for a foreground fallback.

OpenCode 1 receives a plugin using the native `@opencode-ai/plugin` API; OpenCode 2 keeps the `@opencode/plugin` implementation. Both register the same bounded tool actions. Anvil asks for approval before the Analytics materialization tool runs; full-table materialization also requires its explicit confirmation flag.

No existing Analytics data is rewritten by this migration. On first use, SQLite creates or advances its versioned schema under `~/.anvil/analytics/`. Runtime identity and session state are separate from durable SQLite context. The global workspace, SQLite knowledge/history, Parquet snapshots and materialization operation state remain outside lifecycle backups.

Rollback restores the prior Anvil-managed config, removes the Anvil-owned service unit if the restored package lacks Analytics, and keeps Analytics user data. A later upgrade can reuse that state. It does not downgrade a SQLite schema or delete datasets.

```bash
make rollback
```

Core Anvil commands remain usable if DuckDB, PyArrow, OpenCode, Databricks auth or workspace access is unavailable. `make inspect`, `make doctor`, and `make capabilities` report the corresponding Analytics state. See the [Analytics guide](../analytics-workspace.md).

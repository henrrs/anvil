# Anvil 2.18.0 → 2.19.0 migration

This is an Anvil-only upgrade. It preserves the selected OpenCode major/executable, Databricks authentication, local Parquet generations, favorites, and saved Analytics context. The SQLite context store migrates from schema 4 to 5 for identity and chat projection, using the lifecycle's consistent backup-and-restore rollback policy.

```bash
git pull
make upgrade DRY_RUN=1
make upgrade
make analytics-status
make doctor
```

On startup, Anvil migrates older LocalDataset pointer metadata and validates existing Parquet against DuckDB. A valid local copy becomes READY without fetching it again. If the physical schema truly disagrees, the UI asks to update the local copy; technical reconciliation is not a manual step.

All rows acquisition no longer has an implicit 1,000,000-row ceiling. A transfer may use more disk and time; the UI reports measured progress and keeps CURRENT active until a complete new generation is verified. Failed transfers can resume completed chunks while the remote result remains valid. Different tables can materialize concurrently, with one writer per table; set `ANVIL_ANALYTICS_MATERIALIZATION_WORKERS` to 1–8 only if the default of 2 needs adjustment.

Ask Anvil messages reappear after a page refresh. Confirming Clear conversation starts a new canonical session but retains saved context and local data. The header resolves the Databricks user or service principal from the selected Anvil profile, using its last verified value during an outage.

`make upgrade DRY_RUN=1` is read-only and requires no network. The actual upgrade may need the configured Python package source. If a lifecycle issue occurs, use `make inspect` and `make rollback`; do not remove Analytics data manually. See the [operations guide](../analytics-workspace-operations.md) and [engineering report](../analytics-local-reliability-report.md).

# Anvil 2.3.1 to 2.4.0 migration

Anvil 2.4.0 adds safe runtime quiescing during Anvil upgrades, human-first command output, and environment-aware Databricks onboarding. It does not require OpenCode 2 and does not change the configured OpenCode runtime.

## Upgrade Anvil

```bash
git pull
make test
make doctor
make upgrade DRY_RUN=1
make upgrade
make doctor
```

The dry run reports active OpenCode processes and performs no live mutation. A real upgrade checks the config, runtime, backup destination, and local space first. After confirmation, it shows a countdown, sends SIGTERM to only the validated OpenCode process using this installation's configured data paths, and waits for graceful shutdown. SIGKILL is used only if that bounded wait expires. Anvil verifies that the process has exited before creating an Anvil-only backup. If Anvil was opened from inside that OpenCode session, the upgrade aborts before signaling; rerun it from an external terminal. OpenCode remains stopped after the upgrade and can be started normally.

`make update-runtime` and `make migrate-runtime OPENCODE_MAJOR=N` remain the explicit runtime-change operations. `make upgrade` preserves the exact validated OpenCode executable and version and requires no release-service access.

## Configure Databricks

Run:

```bash
make databricks-setup
```

Setup owns supported CLI installation and authentication orchestration. On a local interactive terminal it can run the official Databricks CLI OAuth U2M flow after you select the workspace. In a supported Azure remote session it can use Azure CLI device-code login and the Databricks SDK. For remote AWS/GCP or headless environments it guides you to an existing Unified Authentication profile or the official VS Code extension rather than trying an unreliable local browser callback.

Preview local discovery without network or state changes with `make databricks-setup DRY_RUN=1`. Request full JSON with `make databricks-setup OUTPUT=json`, or local diagnostics with `make databricks-setup VERBOSE=1`. Existing valid profiles are reused; Anvil stores provider/authentication metadata only.

See [Anvil 2.4.0 release notes](../versions/v2.4.0.md), [Databricks setup](../databricks/setup.md), and [Databricks authentication](../databricks/authentication.md).

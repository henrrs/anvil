# Anvil 2.17.1 → 2.18.0 migration

Anvil 2.18.0 is an Anvil-only upgrade. It preserves the installed OpenCode executable and major, existing Databricks authentication, Analytics workspace data, local Parquet generations, and SQLite schema. No new database migration or manual dependency installation is required. Its automatic same-major source window expands to twelve prior minors so supported Anvil 2.6.x installations remain upgradeable.

## Upgrade

```bash
git pull
make upgrade DRY_RUN=1
make upgrade
make analytics-status
make doctor
```

The dry run shows the release manifest and managed-file plan. The upgrade prepares and validates the same release-pinned Analytics runtime used by this checkout before activating the managed files and service. If a configured package registry is unreachable, the current installation remains available and the command reports the dependency source failure.

## Behavior changes

- LOCAL and fully covered AUTO queries no longer require Databricks warehouse discovery. Incomplete or physically inconsistent local coverage fails clearly or routes AUTO remotely when available.
- Materialization operations abandoned by a service restart become structured failures. Retry is a fresh operation; old worker state is not resumed. Existing CURRENT data remains available during update/failure.
- Removing a local copy is serialized against table writers. It removes Anvil's local generations and local coverage entry only; remote catalog data, favorites and query history are preserved.
- Analytics status distinguishes Databricks configuration, authentication, TLS, workspace and warehouse discovery. Local capability states are independent.
- Ask Anvil prefers Luna 6 through GitHub Copilot and validates the active runtime provider catalog before every prompt. If GitHub Copilot is not connected or does not expose Luna 6, the request reports that state and does not silently choose another model.

No `make reforge`, runtime migration or Databricks reauthentication is part of this migration. See the [Analytics operations guide](../analytics-workspace-operations.md) and [correctness/recovery guide](../analytics-local-correctness-hardening.md).

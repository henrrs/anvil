# Anvil 2.9.0 to 2.10.0

This release changes task-depth guidance and scoped architecture evidence. It does not migrate the OpenCode runtime, task-state schema, Databricks profile, memory, or communication artifacts.

```bash
git pull origin master
make test
make upgrade DRY_RUN=1
make upgrade
make doctor
make capabilities
```

The Anvil upgrade preserves the exact validated OpenCode executable/version. It keeps existing `${XDG_STATE_HOME:-$HOME/.local/state}/anvil/engineering/` state at schema 1. Local requests no longer activate engineering state merely because the repository has many files, requirements, milestones, or a lengthy specification. For a genuinely structured continuation, resume it explicitly or ask Anvil to continue the named work.

`engineering.py assess` now reports `DIRECT` or `EXPAND` based on supplied task-local signals. `EXPAND` means use only the relevant evidence branch; it does not initialize a plan/state. Project-size counts and long request text are advisory. Existing CLI users should not parse `LONG_HORIZON` from assessment output.

Milestone architecture checks can now be scoped:

```bash
python3 "${XDG_CONFIG_HOME:-$HOME/.config}/opencode/scripts/engineering.py" checkpoint \
  --repository /path/to/project --id TASK --revision N --milestone M3
```

This requires the milestone's task/check gates to be complete, checks only its declared missing or stale mechanical invariants, and preserves still-valid evidence in unaffected scopes. Omit `--milestone` for a full explicit architecture audit. A local file change invalidates invariant evidence only when its declared file/pattern scope is affected.

The automatic source migration window now spans four previous minor releases, preserving support for 2.6.x profiles previously supported by Anvil 2.9.0. OpenCode 1 and 2 remain supported without a runtime update. Rollback preserves the same prior Anvil/OpenCode and task-state boundaries.

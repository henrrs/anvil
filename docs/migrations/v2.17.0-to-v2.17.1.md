# Anvil 2.17.0 → 2.17.1 migration

Anvil 2.17.1 is an Anvil-only patch. It keeps the installed OpenCode runtime version and major. The release improves real-machine convergence for the Analytics service, dependencies, runtime recovery, lifecycle journal and SQLite control-store rollback.

The target release must come from a committed, verifiable checkout. A production `make upgrade` stops before snapshot creation or dependency staging if a release-owned file differs from `HEAD`; commit or revert release artifacts before retrying. `make upgrade DRY_RUN=1` is read-only and reports the selected package source policy without network availability checks.

## Preview and upgrade

```bash
make inspect
make doctor
make capabilities
make upgrade DRY_RUN=1
make upgrade
make inspect
make doctor
make capabilities
make analytics-status
make upgrade
```

The first real upgrade repairs only hash-verified Anvil-managed drift and user-owned path collisions remain protected. It prepares and validates the release-pinned Python environment before activating its config and service. Systemd candidate syntax is checked before activation when `systemd-analyze` is available. The final `make upgrade` checks idempotency; with no drift, it should not rebuild dependencies, regenerate the service, recreate the canonical Analytics session, migrate the database or restart OpenCode.

## Package sources

Anvil reads but does not rewrite existing pip configuration. An explicit Anvil package index takes precedence, then configured pip corporate sources; public PyPI is used only when the existing fallback policy enables it. Existing credentials are redacted in logs, and credentials from unrelated tools are not collected. If the corporate registry is unavailable or authentication is rejected, resolve that network/configuration condition and rerun `make upgrade`; do not install packages into system Python.

## SQLite and rollback

The SQLite control database has a declared per-migration rollback policy. If a transition requires restoration, Anvil creates and verifies a transactionally consistent SQLite backup before activation. On failure, rollback restores the previous managed config and runtime pointer, restores the database only when the migration contract requires it, then restores and verifies the baseline service. Large datasets and Parquet materializations are not duplicated. Unknown/non-rollbackable schema transitions stop before activation.

Interrupted staging, activation, restoration and committed-but-unfinalized states are classified from the durable journal. Supported recovery runs automatically on the next mutating lifecycle command; a journal with unknown state blocks while preserving the verified snapshot. A manual journal clear is not part of normal recovery.

If a legacy foreground Anvil Analytics server owns the selected port, Anvil stops it only when process user, command, working directory and port match. An unknown port owner is left untouched. Use `make analytics` for the managed service and reserve `make analytics-dev` for explicit foreground development.

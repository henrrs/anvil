# Anvil 2.7.1 to 2.8.0 migration

Anvil 2.8.0 adds a managed-file manifest and uses semantic Anvil version ordering. Existing 2.6.x and 2.7.x installations are supported source states and do not need `make reforge` for a normal product update.

## Upgrade

From the updated repository, run:

```sh
make inspect
make upgrade DRY_RUN=1
make upgrade
make doctor
```

The dry run reports managed files to add, update, or remove, user-owned files it will preserve, and the OpenCode runtime it will keep. It does not stop OpenCode, create a snapshot, or write to live paths. Close OpenCode when running the real upgrade; Anvil creates and verifies a rollback snapshot before applying the transition.

If a user-owned file occupies a path newly claimed by Anvil, the upgrade stops before mutation and names the path. Move that file to a different path and rerun the dry run. Extra global files outside Anvil's manifest remain in place across upgrade and reforge.

Upgrade preflight checks that the parent directory of `$XDG_CONFIG_HOME/opencode` (default `~/.config`) is writable, because Anvil activates the new config by an atomic sibling-directory rename. If it reports a read-only config parent, restore write/search permission and rerun `make upgrade DRY_RUN=1` before retrying the upgrade. This check happens before OpenCode is stopped or a snapshot is created.

If `make inspect` reports `UNSUPPORTED` because the installed Anvil release is newer than this checkout, do not run `make reforge` from the older checkout. Switch to the installed release or a newer repository checkout; both upgrade and reforge block downgrades.

## Interrupted operation

If power loss or `SIGKILL` interrupts the change, `make inspect` reports `RECOVERY_REQUIRED`. Close OpenCode, then rerun the same lifecycle command. Anvil validates the journal's snapshot, restores it, clears the journal, and continues. `make rollback` restores the interrupted operation's snapshot and exits. If the journal or snapshot is invalid, Anvil stops without overwriting the current state and reports that manual review is needed.

## Runtime operations

`make update-runtime` changes OpenCode within the current major and preserves the installed Anvil release/config. `make migrate-runtime OPENCODE_MAJOR=1|2` changes the runtime major and config adapter, so it is allowed only after Anvil itself is current. Neither operation is required for this Anvil migration. `make upgrade` never performs OpenCode release lookup or changes the executable.

Rollback restores the matching config and installation metadata. When it restores an older but supported Anvil release, the current checkout reports `MIGRATION_REQUIRED`; rerun `make upgrade` to return to the current release.

# Anvil 2.11.0 to 2.12.0

Anvil 2.12 adds ownership-aware OpenCode profile merging and narrows rollback snapshots to Anvil-managed files plus the shared profile/preferences. It retains OpenCode 1 and 2 support and expands the same-major Anvil source window to six prior minor releases so supported 2.6.x installations remain upgradeable.

Preview the local transition first:

```bash
git pull origin master
make test
make upgrade DRY_RUN=1
make upgrade
make doctor
```

The dry-run prints counts and a bounded path sample. It states which OpenCode settings are shared and merged, which local paths remain outside Anvil ownership, and whether the operation will create a scoped snapshot. It does not print config values or secrets. Reforge uses the same preservation rules when rebuilding Anvil-owned files.

The shared `opencode.jsonc` file retains external plugins, MCP servers, references, provider settings, user agents, runtime preferences and unknown keys. The V1/V2 adapter converts supported provider, plugin, MCP and agent config forms during an explicit runtime migration. The V2 Anvil core plugin remains present alongside external plugins. Anvil adds no MCP servers itself. `cli.json`, `tui.json`, and `tui.jsonc` preferences remain user-owned.

Snapshots include Anvil-managed config files, the shared OpenCode profile, and CLI/TUI preferences. External config files remain live and are not copied into each archive. Rollback restores the snapshot to a private stage and merges current user-owned files and shared settings before activating it. If a current user-owned path conflicts with a path owned by the prior Anvil profile, rollback stops with the live config unchanged for manual review.

Package repository settings, proxy/certificate configuration, credentials/references, Databricks profiles and shell startup files outside the OpenCode config directory are not changed by Anvil profile upgrades, reforge, or rollback. OpenCode runtime/data/state rules, Databricks state, Anvil Markdown memory, engineering task state, public Make targets and provider independence remain unchanged.

The 2.12 candidate is **NOT RELEASE READY**: it keeps the prior presentation-benchmark release blocker. The repository still has no current Anvil PPTX/GIF deck for before/after review, and no live model was available for latency evaluation. See the [environment and editorial engineering report](../environment-preservation-v2.12-report.md) and [ADR-0020](../decisions/ADR-0020-editorial-intelligence-and-local-config-preservation.md).

# Anvil 2.12 Engineering Report

**Release recommendation: NOT READY.** This candidate is **NOT RELEASE READY** because the actual Anvil presentation benchmark and live-model responsiveness evaluation required by the specification are unavailable. Offline structural and lifecycle checks can verify contracts and preservation behavior, but they cannot establish semantic presentation quality or model latency.

## Current Architecture Assessment

Anvil already has runtime-independent artifact contracts and a renderer/reviewer package under `scripts/communication`, Markdown/SVG output, quantitative evidence checks, a lazy artifact skill, and a shared lifecycle pipeline. Its install, upgrade, runtime update/migration, reforge, doctor, backup, transaction journal, and rollback operations use the managed-config manifest and staged config activation. This iteration extends those boundaries; it adds no service, framework, dependency, agent, or public Make target.

| State | Ownership and handling |
| --- | --- |
| Manifest-listed Anvil files: harness instructions, shipped commands/skills/scripts, and V2 core plugin files | Anvil-owned; generated from the repository and audited by the manifest. |
| Anvil profile fields and Anvil agent/plugin/reference identity | Recorded as managed profile ownership in the manifest and regenerated by the existing config builder. |
| `opencode.jsonc` | Shared: Anvil-managed profile fields are rebuilt while providers, external plugins/config, MCP, references, custom agents, runtime preferences, and unknown keys are merged. |
| CLI/TUI preferences and other regular user files under the OpenCode config root | User-owned; carried through staged rebuilds. Preferences are included in the scoped snapshot; external extras remain in place and are reconciled at rollback. |
| Package repositories, Nexus/mirrors, proxies, certificates, trust stores, credentials, shell files, Databricks config, and paths outside the OpenCode config root | Outside this lifecycle's mutation/snapshot scope; not copied into Anvil config archives. |

## Existing Components Reused

- `config/skills/anvil-communication/SKILL.md` remains the only home for artifact editorial guidance. It is loaded for artifact work and leaves simple code tasks on the existing fast path.
- `scripts/configure.py` continues to own OpenCode V1/V2 profile construction and schema conversion.
- `scripts/managed_config.py` extends the current ownership manifest, source inspection, transition plan, snapshot, and rollback reconciliation.
- Existing sibling staging, atomic activation, verified archive, lifecycle transaction journal, and recovery flows remain in use.
- Existing `scripts/communication` contracts/renderers are unchanged; no deterministic taste engine was introduced.

## Artifact Intelligence Changes

The lazy skill now guides the model to establish trustworthy context before interpreting metrics; separate observed change from materiality; connect findings to insights and implications; remove or merge redundant content; model semantic relationships before selecting visuals; question weak charts; annotate evidence directly; use whitespace and asymmetric hierarchy; state supported conclusions in titles; and make each animation step add understanding. A single lightweight semantic review remains model-driven. Simple artifact edits stay scoped to the requested change.

Missing benchmarks remain unknown; the guidance forbids invented good/bad/healthy/critical classifications. Materiality considers context and consequence without requiring formal significance tests. Semantic relationships and composition influence visual choices without coordinates, fixed slide templates, or hard-coded aesthetic acceptance.

Eleven synthetic fixture cases cover stable and material metrics, concentrated contribution, missing benchmark, redundant slides, weak chart, direct annotation, sparse executive message, decorative motion, progressive process, and feedback loop. `tests/communication.py` checks fixture structure and declared expected judgments; it does not run or score a live model.

## Local Configuration and Lifecycle Preservation

### OpenCode plugin preservation

Config rebuilds merge supported V1/V2 provider, plugin, MCP, reference, and agent forms, external plugin configuration, user preferences, and unknown keys. Malformed shared config or an incompatible plugin shape fails before activation rather than silently discarding values. Existing unowned files and symlink objects under the config directory are retained by staged rebuilds, subject to collision checks.

Before lifecycle mutation, the existing backup flow now snapshots only manifest-owned files plus the shared profile and CLI/TUI preferences. Unrelated external config files, package-manager trees, symlinks outside the selected snapshot, and machine files outside the OpenCode config root are excluded. Rollback restores Anvil-owned files to a private sibling stage, merges current external files and shared settings, validates ownership collisions, then activates through the existing atomic config swap. If a current user-owned path collides with a path owned by the old Anvil profile, rollback stops before changing live config and reports the conflict.

Dry-run plans state the ownership and preservation scope, use bounded summaries, and avoid printing config values. Lifecycle code preserves references to credentials rather than creating new plaintext copies. Existing backup behavior for runtime-scoped OpenCode executable/data/state remains unchanged.

Enterprise repository/mirror, proxy, certificate, trust, shell, Databricks, and other machine configuration outside the OpenCode config root is not read or rewritten by this change. Reforge and upgrade only stage the configured OpenCode config directory; external machine settings remain at their existing paths.

## Tests and Baseline vs Candidate Observations

New lifecycle regressions exercise first use with an external profile, V1/V2 settings and plugin/MCP merge, user files and preferences, dry-run non-mutation/redaction, Anvil-only scoped snapshot contents, post-upgrade edits and symlinks surviving rollback, reforge preservation, and six-minor source compatibility. Concurrent lifecycle runs reserve timestamped backup directories atomically. They use isolated HOME/XDG fixtures. The complete `make test` suite passed, including existing lifecycle recovery, failure injection, upgrade, runtime, rollback, Databricks, communication, and engineering cases.

The prior `anvil-communication` skill was 11,610 bytes; the candidate is 13,874 bytes (+2,264 bytes, about 566 byte/4 tokens). That guidance is lazy and only loaded for artifact tasks. The always-loaded `config/AGENTS.md` grows from 3,338 to 3,511 bytes (+173 bytes, about 43 byte/4 tokens) and remains below the 4,200-byte budget. These are context-size observations, not measured model latency.

No current Anvil PPTX/GIF or supported rendered deck exists in the repository, so no valid real-artifact before/after comparison can be reported. The synthetic fixtures demonstrate coverage targets only; they are not evidence of improved editorial judgment. No live model was available to evaluate quality, tool/context use, or responsiveness. No latency or token benchmark is claimed.

## Backward Compatibility and Limitations

OpenCode 1.x and 2.x remain supported; product/runtime versions remain independent. New manifest ownership arrays are optional, so prior schema-1 manifests remain readable. No OpenCode runtime, persistent-data, Databricks, memory, or external package dependency migration is introduced. The automatic source window now includes six prior Anvil minor releases. Public lifecycle commands and Make targets are unchanged.

The shared JSONC profile is parsed and serialized as JSON, so comments and original formatting are not retained even though recognized values and unknown keys survive. Unsupported/malformed configuration fails before live replacement. A collision between current user-owned and prior Anvil-owned paths requires manual review. The current repository has no binary PPTX/DOCX/PDF, quantitative chart, OCR, or dynamic animation renderer; this refinement does not add one.

## Performance Impact and Release Recommendation

Routine coding receives only the measured +173-byte always-loaded instruction increase; the 2,264-byte editorial addition remains lazy. No live-model latency comparison was run, so responsiveness is **NOT MEASURED**. The real deck comparison and live responsiveness evaluation are release blockers from the implementation specification.

Release recommendation: **NOT READY** until a real Anvil deck and generation inputs are reviewed before/after through the supported artifact path and a live-model responsiveness comparison is recorded. Do not infer semantic quality from fixture integrity or claim that absent benchmark has passed.

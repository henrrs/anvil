# Public Make command contracts

Anvil treats its Make targets as a public command API. Lifecycle labels come from [`lifecycle_state.py`](../scripts/lifecycle_state.py): `REPOSITORY_ONLY` has no Anvil-managed state; `PARTIALLY_INSTALLED` has managed artifacts but lacks a valid config/runtime pair; `INSTALLED` has a supported runtime and valid config; `READY` also has release-matching install metadata; `DEGRADED` remains usable with a missing non-core memory directory; `CORRUPTED` has a malformed or unsafe managed artifact. `BLOCKED` is an operation result, not a saved installation state.

GNU Make may append its standard non-zero recipe line after Anvil's diagnostic. A non-zero code means the requested operation did not complete. Informational commands return zero when they successfully report an absent or degraded capability.

| Target | Purpose and allowed states | Side effects | Network/runtime behavior | Success and blocked result | Exit semantics |
| --- | --- | --- | --- | --- | --- |
| `make help` | List targets and lifecycle guidance; every state | None | No network or runtime invocation | Prints command summary | `0` |
| `make inspect` | Read-only inventory; every state, including partial/corrupted | None | Local filesystem/runtime/provider inventory only | Prints lifecycle classification and paths; never repairs state | `0` when inspection completes |
| `make reforge` | Bootstrap or rebuild; repository-only, partial, installed, ready, degraded | Stages config, records state, creates a verified rollback snapshot; may install runtime only when none exists | Reuses a healthy supported OpenCode runtime exactly; clean first install may resolve/download approved runtime | Prints postflight result; blocks unsafe paths, active processes, or an unhealthy/unsupported existing runtime before live mutation | `0` completed, non-zero blocked/failed |
| `make upgrade [DRY_RUN=1]` | Update Anvil around an existing valid config and supported runtime; installed, ready, degraded | Real run quiesces OpenCode, snapshots Anvil state, updates config/metadata, and leaves runtime/data/state intact; dry run is read-only | Offline; preserves exact OpenCode executable/version | Reports plan or completed Anvil release; repository-only/partial/corrupted is blocked with `make reforge` guidance | `0` completed, non-zero blocked/failed |
| `make update-runtime [DRY_RUN=1]` | Explicit same-major OpenCode update; installed, ready, degraded | Real run stages, rehearses, backs up, installs and postflight-validates runtime | Network required for release resolution/download; changes runtime within its current major | Reports plan/completion; missing Anvil config/runtime, unsafe state, or unreachable release is explained before live mutation | `0` completed, non-zero blocked/failed |
| `make migrate-runtime OPENCODE_MAJOR=1|2 [DRY_RUN=1]` | Explicit OpenCode major migration; installed, ready, degraded | Real run stages/rehearses, snapshots and changes runtime/config adapter | Network required; migrates only to the requested supported major | Reports plan/completion; invalid target or missing installation is blocked with next action | `0` completed, non-zero blocked/failed |
| `make doctor` | Diagnose Anvil/runtime/project and configured Databricks readiness; every state | Read-only | No release lookup; configured Databricks profiles trigger bounded read-only workspace probes unless `ANVIL_DOCTOR_LOCAL=1` | Reports `NOT_INSTALLED`, partial, degraded, healthy, or broken state and relevant next step | `0` healthy/informational, `2` warnings/partial state, `1` corrupted or failed checks |
| `make capabilities [FORMAT=json]` | Report runtime and optional Databricks capabilities; every state | None | Local inventory and cached Databricks evidence only | Prints text or one JSON document; unavailable runtime/features are reported, not treated as command failure | `0` when capability inspection completes |
| `make stats` | Show OpenCode-native stats when available; every state | None; uses a temporary output directory that is removed after rendering | No release lookup; invokes the validated local runtime only | Reports no stats before runtime install or on unsupported/failed native stats without inventing values | `0` for an honest unavailable/fallback report; non-zero for invalid arguments or internal failure |
| `make rollback` | Restore latest verified snapshot; requires a valid snapshot | Restores only the snapshot's recorded Anvil/runtime scope; archives current memory before restore | Offline; runtime changes only for runtime-scope snapshots | Reports missing/corrupt snapshots as `BLOCKED` and explains how to create a snapshot | `0` restored, non-zero blocked/failed |
| `make databricks-setup [DRY_RUN=1]` | Configure optional Anvil-owned Databricks provider; independent of OpenCode lifecycle | Dry run is read-only; real run may install CLI/SDK, authenticate, stage/promote Anvil-owned config and save non-secret readiness | Dry run offline; real setup may contact official provider/package sources and the selected workspace; never requires OpenCode 2 | Reports provider, readiness, root blocker, impact, and next action; missing pip is a structured SDK blocker while a healthy CLI can remain primary | `0` dry run or READY/DEGRADED; non-zero if real requested setup is not ready or fails |
| `make test` | Run offline contract and lifecycle regression suite; every repository state | Writes only inside a temporary test root, removed on exit | Denies external network in lifecycle tests; uses local OpenCode/Databricks/Python fixtures | Reports each contract check and stops on the first failed assertion | `0` all checks pass, non-zero otherwise |

## Human output and diagnostics

Public human output does not use raw JSON or Python tracebacks as its primary result. Databricks setup's `OUTPUT=json` and capability `FORMAT=json` remain the machine-readable interfaces. Python command entrypoints render unexpected failures with a diagnostic ID; `DEBUG=1` adds stack frames and a redacted exception summary. Debug output must not include tokens, credentials, or arbitrary SDK response bodies.

## Test isolation contract

`make test` assigns temporary `HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`, and `XDG_STATE_HOME`, constrains `PATH` to the selected Python directory plus standard system binaries, disables the user Python site directory, and clears inherited Databricks selectors. Tests must use local doubles and may not read or mutate the developer's profiles, managed OpenCode installation, user venv, or XDG data.

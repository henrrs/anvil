# Analytics local reliability engineering report

This report covers the incremental LocalDataset, materialization, identity, chat, and Home changes following Anvil 2.18.0. It records the offline certification boundary explicitly; no live corporate Databricks workspace or installed OpenCode instance was exercised from this checkout.

1. **Legacy LocalDataset root cause.** The prior release's local schema verifier raised `NameError` while parsing a type. The caller reported the valid Parquet as unverified, which surfaced as a reconciliation problem after upgrade.
2. **Exact validator defect.** Type canonicalization has moved into `scripts/analytics/schema.py`; it imports its own parsing dependencies and accepts native Arrow types. Unexpected `NameError`, `AttributeError`, `KeyError`, and `TypeError` are classified as `INTERNAL_SCHEMA_VALIDATION_ERROR`, separate from an actual physical mismatch.
3. **Versioned LocalDataset state.** `dataset-state.json` is normalized to schema version 2 with table identity, coverage, source schema, physical schema, generation pointers, and timestamps. Existing `current.json` pointers remain readable and are mirrored for compatibility.
4. **Reconciliation.** Startup migrates cheap pointer metadata, then a background pass validates CURRENT through Parquet footers and DuckDB. It writes canonical physical column types and nullability only after independent validation; unchanged verified files use an evidence fingerprint to avoid repeated full hashing.
5. **User-facing state.** `NEEDS_RECONCILIATION` does not appear in the API or Home. Safe reconciliation is automatic; an unrepairable schema mismatch appears as “Local copy needs to be updated.” An internal validator fault leaves the copy unavailable for that query without marking it physically invalid.
6. **Previous-release compatibility.** A physical fixture builds a table-only-key legacy snapshot with 37 columns and 468,684 rows. After service startup, state is migrated, physical schema is recorded, and both `SELECT * ... LIMIT 100` and `SELECT count(*)` execute through DuckDB without rematerialization.
7. **Hidden row cap.** UI and tool requests previously supplied implicit `max_rows` and `max_bytes` values, and the plan inserted a SQL `LIMIT`. This could make “All rows” a bounded copy.
8. **All rows contract.** An unbounded acquisition plan leaves both limits absent from the Databricks request and SQL statement. Explicit `max_rows` remains an advanced API option; it produces `LIMITED` coverage. Manifest row/byte totals are checked before activation, and reported truncation fails publication.
9. **Arrow retry.** Each chunk has bounded network/HTTP retries with backoff and jitter. Expired signed links are refreshed; retryable transfer errors preserve completed chunks and their checksums. A per-chunk byte bound and free-space checks protect local storage without truncating the logical result.
10. **Checkpoint and resume.** A checkpoint records statement/result fingerprint, chunk index, row/byte counts, Parquet hash, and progress totals. Retry verifies the remote result and staged files before reusing completed chunks. Process restart marks interrupted work resumable where evidence is sufficient.
11. **Remote expiration.** A closed/missing result or explicit expiration code removes only its partial staging and schedules a clean new generation. A temporary provider check failure preserves the checkpoint for a later retry. CURRENT is unchanged until publication.
12. **Scheduler.** A dedicated FIFO `ThreadPoolExecutor` separates local transfers from catalog/chat work. It accepts requests for different tables and queues excess work. `ANVIL_ANALYTICS_MATERIALIZATION_WORKERS` selects 1–8 workers; the default is 2.
13. **Concurrency policy.** Distinct tables may transfer concurrently. Queued and running counts are exposed in runtime metrics. A queued operation can be cancelled without starting its worker.
14. **Per-table lock.** A process-held `materialization.lock` lease is acquired before queuing, so a second mutating request for the same workspace/table reuses or reports the existing operation instead of creating a second writer.
15. **Progress.** Progress uses committed chunk rows divided by the remote planned row count, clamped to 0–100%. The UI shows rows, bytes, chunks, and percentage when known; unknown totals show measured amounts without a fabricated percentage. The 630,784 / 4,714,788 row fixture reports 13.4%.
16. **Identity.** The selected Anvil Databricks profile supplies `current-user me` through the shared CLI capability. A private SQLite cache keyed by workspace retains the last verified display name during outages. No OS/WSL username fallback is used; service principals retain their type and principal.
17. **Chat persistence.** Visible user/assistant messages are projected into private SQLite by canonical session ID. Reload pages the current conversation; when projection is absent, the service can rebuild visible messages from the canonical OpenCode session. OpenCode remains the cognitive authority.
18. **Clear conversation.** Confirmation rotates the canonical session pointer and increments its generation, then clears the visible thread. Saved Analytics context, local data, favorites, and model policy remain available. Older projected messages remain tied to the old session and are not loaded into the new thread.
19. **Home.** Active/queued/failed operations appear first, followed by side-by-side recent tables and queries, local data/recent activity, and pinned items. Failed operations expose Retry or Resume; valid legacy copies appear as local data without technical reconciliation language.
20. **Responsive and accessible UI.** Firefox geometry checks cover 1366×768, 1920×1080, 2560×1440, 3840×2160 and 125%/150% scaling. Progress bars expose accessible values when known. The clear confirmation stays inside the Ask Anvil panel. The production and mock HTML were aligned; baseline and final Home screenshots were visually compared.
21. **Tests.** Added or extended fixtures for the legacy physical snapshot, native/text type normalization, 4.7M-row transfer with failure after seven chunks, expired result, known/unknown progress, FIFO queue/cancellation, Databricks identity, chat pagination/clear, and mock scenarios. The physical fixture uses the pinned DuckDB/PyArrow environment; system Python may skip it.
22. **Real-machine rehearsal boundary.** The previous-release dataset is represented by actual Parquet files and exercised locally end to end. Full 4.7M-row and network scenarios use deterministic provider/codec fixtures so they do not allocate or download millions of real rows. A live corporate workspace, browser on WSL host, and installed OpenCode session remain for machine-specific follow-up.
23. **Full regression.** `make test` passed all Anvil offline checks, including 169 Analytics tests (three physical-dependency cases skipped under system Python). The pinned DuckDB/PyArrow environment ran all 169 Analytics tests without skips. `make eval-analytics` passed 148 checks. `python3 scripts/analytics_ui_visual_check.py` passed the responsive and scenario checks, with final screenshots under `artifacts/analytics-local-reliability/ui/final/`. `python3 scripts/version_docs.py` and `git diff --check` also passed.
24. **Limits.** The query response window remains bounded independently of acquisition. Local routing still requires provable single-source coverage. Unknown remote totals cannot yield an honest percentage. Signed result retention is controlled by Databricks; a result that expires before retry requires a fresh transfer. Browser screenshots validate the mock rather than a live workspace.

The visual baseline is in `artifacts/analytics-active-tab-indicator/final/`; the new Home and operation scenarios are in `artifacts/analytics-local-reliability/ui/final/`.

# Offline Databricks tests

The mandatory suite uses `tests/fixtures/bin/databricks` as a local CLI double. Setup installer behavior is tested with a local fake GitHub release archive, a generated SHA-256 manifest, and injected permission/policy failures; it never downloads a real CLI. SDK operations use mocked provider contracts and local profile fixtures. VS Code detection uses a fake `code --list-extensions` executable.

Coverage includes provider ranking, CLI preference, SDK fallback for workspace, job, pipeline, compute, Python and SQL operations, SDK request type/method contracts, Azure CLI SDK auth construction, VS Code assisted state, Connect/Bundles capability reporting, cached absolute CLI paths across PATH changes, classified install failure, profile migration, provider-state permissions and secret rejection, idempotent setup, topology-aware auth selection, timeout/cancellation/device-code fakes, human/JSON presentation, and a no-write/no-network dry-run. Lifecycle tests hold local runtime fixtures to validate active-process dry-run, graceful shutdown, forced-stop fallback, self-ancestor protection, unrelated XDG process isolation, preflight failure, and cancellation.

The full `make test` suite runs OpenCode 1 and 2 fixtures and isolated lifecycle, upgrade and rollback scenarios. It requires local Python 3.11+, Bash and system utilities already used by Anvil. Mandatory tests do not resolve/download OpenCode, access GitHub or PyPI, contact Databricks, open an OAuth flow, or call an LLM. No live workspace validation was run for this release.

# Offline Databricks tests

The mandatory suite uses controlled executables and local fakes for `tests/fixtures/bin/databricks`, Azure CLI, SDK, installer archive, and VS Code CLI. It does not open a browser, perform real OAuth, access a Databricks workspace, or require network access. The tests do not resolve/download OpenCode.

Coverage includes clean `anvil-dev` creation, legacy external-profile migration, multiple external profiles, no external-profile adoption or modification, Anvil config ownership/collision/corruption handling, atomic reset backups, `0600` config/state files and `0700` directories, environment override isolation, secret-free diagnostics, Azure CLI session reuse/device-code orchestration, topology-aware auth selection, CLI OAuth U2M fallback, idempotency, SDK use of the explicit Anvil config file/profile and persisted absolute interpreter, CLI/SDK provider routing, readiness state transitions, false-READY prevention, clean-process status and resource discovery, setup-time SDK provisioning after a provider-specific CLI health timeout, stop-on-shared-failure behavior, blocked SDK installation, metadata-list timeout routing, public `make doctor`, `make databricks-setup DRY_RUN=1`, and `make capabilities` contracts, setup interruption rollback, expired-auth invalidation, empty core-resource lists, permission-scoped partial availability, shared network/auth blocker propagation, provider-specific timeout and malformed-JSON fallback, normalized error metadata, slow-but-valid calls, bounded aggregate output, child-process cleanup, command-parser examples from the Databricks skill, human/JSON presentation, and dry-run no-write behavior.

The full `make test` suite exercises both supported OpenCode runtime profiles and existing lifecycle, upgrade, rollback, network-denial, runtime-independence, and organization-hygiene regressions. It requires local Python 3.11+, Bash, and the utilities already used by Anvil. No live workspace validation is claimed.

# Anvil 2.19.0 — Analytics Local Reliability

Anvil 2.19.0 is an incremental Analytics release for OpenCode 1.x and 2.x. It retains the release-pinned DuckDB/PyArrow dependencies in `config/analytics-requirements.lock` and requires Python 3.11+. It does not migrate the OpenCode major, Databricks credentials, or local Parquet data. The SQLite context store moves to schema version 5 with an explicit backup-and-restore rollback policy. The same-major source window covers thirteen prior minor releases, retaining supported 2.6.x installations.

## Changes

- Legacy LocalDataset pointers and metadata are migrated at startup. CURRENT Parquet is checked with PyArrow and DuckDB, and valid copies return to READY without a remote transfer. Internal validator faults are diagnosed separately from actual schema mismatch.
- All rows materialization sends no implicit SQL row limit or Statement Execution `row_limit`/`byte_limit`. Explicit row bounds create LIMITED coverage. Transferred row/byte totals and truncation are validated before activation.
- Arrow chunks retry transient network failures and refresh expired links. Valid checkpoints can resume after process restart; an expired remote result triggers a clean generation. CURRENT remains queryable until the new generation is fully published.
- A dedicated FIFO worker pool runs materializations for different tables concurrently while one table retains one writer. Home shows measured progress, known percentage, queue status, and Resume/Retry actions.
- The header uses the authenticated Databricks identity. Ask Anvil history survives refresh, and confirmed Clear conversation rotates the canonical Analytics session while preserving durable context.
- Home groups operations, recent tables/queries, local data/activity and pinned work. The UI remains responsive at 1366×768, 1920×1080, 2560×1440 and 3840×2160.

## Upgrade and evidence

Run `make upgrade DRY_RUN=1`, then `make upgrade`, `make analytics-status`, and `make doctor`. Network required for `make upgrade DRY_RUN=1`: **NO**. Runtime dependency preparation during a real upgrade may need the configured package source. Unity Catalog and warehouse access remain remote capabilities; local copies and query routes remain usable when Databricks is degraded if coverage is proven.

Offline tests and Firefox mock screenshots certify the implementation paths. They do not validate a live corporate warehouse or live GitHub Copilot model availability. See the [migration guide](../migrations/v2.18.0-to-v2.19.0.md) and [engineering report](../analytics-local-reliability-report.md).

# Anvil 2.15.0 — Semantic Foundation Hardening

## Overview

Anvil 2.15.0 hardens the semantic foundation used before analytical interpretation. The profile now distinguishes observations, persistent entities and entity keys, events and event keys, technical keys, dimensions, temporal roles, measures, candidate keys, relationships and observation grain. It keeps evidence and uncertainty visible instead of forcing a complete ontology.

This is a backward-compatible MINOR candidate. Semantic context schema v2 is additive; the validator continues to accept schema v1. No persistent user data, OpenCode configuration, runtime policy or external dependency changes.

## What changed

- Replaced the unique-singleton grain shortcut with bounded composite-key search. Search is capped to a small candidate field set and width three; `FAST` remains width two and `focus=numeric` skips entity/grain discovery.
- Added distinct entity, event, technical-record, and candidate-key roles. Uniqueness alone and `_id` naming alone do not establish an entity. Snapshot entities do not require time recurrence, and multiple entities or no entity are supported.
- Added composite entity-key evidence for identifier components that collide within time and a descriptive component that resolves the observed identity ambiguity. Lightweight functional dependencies identify stable descriptive attributes without treating every attribute as permanent.
- Classified event/business time separately from ingestion and processing timestamps. Technical timestamps do not automatically enter the business grain.
- Added optional source metadata for field roles, entity/event key groups, unique constraints and observation grain, with a normalized fingerprint in profile provenance. Metadata does not equate a database primary key with an analytical entity.
- Downstream entity-count claims use semantic evidence; uncertain entity semantics are qualified and confidence is lowered.
- Added an immutable public 24-case A–X semantic fixture snapshot and a separate hidden answer file. `make eval-analytical-semantic` reports entity precision/recall, high-confidence precision, false-candidate rate, grain and role accuracy, confidence calibration, abstention, event/time role separation, metamorphic stability, ablation/sensitivity results, evaluator mutation detection and bounded performance.

## Compatibility and migration

OpenCode 1.x and 2.x remain supported. `make upgrade` remains Anvil-only and preserves the exact validated runtime. Use `make update-runtime` only when a separate same-major OpenCode update is intended. No semantic state is persisted, so no data migration is needed; regenerate a profile to obtain schema-v2 evidence. Schema-v1 semantic contexts remain accepted for existing profiles and consumers. The same-major source window expands to nine prior minor releases to keep the supported Anvil 2.6.x line upgradeable. **Network required:** no for `make upgrade`; only separate runtime-update/migration operations need release-network access.

## Readiness and limitations

The deterministic semantic foundation reports **READY_FOR_MODEL_EVALUATION** after the L1/L2, adversarial, confidence, abstention and metamorphic gates pass. This is not an L3–L5 result. No live model evaluation or human communication review is included here, so the overall 2.15 candidate remains **NOT READY** for release until those product-level checks are completed.

The analytical evaluation harness is isolated from production and writes immutable, private-by-run reports. Remaining limits include ambiguous identifiers without metadata or domain knowledge, source grain already lost in aggregates, low or biased samples, slowly changing relationships, and nested data outside supported flat-table formats. Confidence describes observed evidence, not a population guarantee.

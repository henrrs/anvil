# Anvil 2.3.1 — Runtime Independence Correction

## Release choice

Anvil 2.3.1 is a patch release. It corrects the lifecycle boundary between Anvil and OpenCode without changing the supported feature set or persistent user-data formats. In particular, a blocked OpenCode release service can no longer prevent a normal Anvil upgrade.

## Three independent lifecycle operations

| Command | Purpose | Network | Changes OpenCode runtime |
|---|---|---:|---:|
| `make upgrade` | Upgrade Anvil files and metadata | No | No; preserves the exact validated executable and version |
| `make update-runtime` | Update within the current OpenCode major | Yes | Yes, after validation and backup |
| `make migrate-runtime OPENCODE_MAJOR=N` | Change OpenCode major explicitly | Yes | Yes, after adapter rehearsal and backup |

`make upgrade DRY_RUN=1` uses the locally installed runtime, validates the target config, rehearses against copied user state, and reports `Network required NO`. It creates no live backup and makes no changes.

## Reforge and local status

`make reforge` now rebuilds Anvil configuration using an existing healthy supported OpenCode runtime without downloading or replacing it. A genuinely fresh installation may resolve and install the runtime selected by `config/runtime-policy.json`. An existing but unhealthy or unsupported executable is reported for explicit repair/update instead of being silently replaced.

`make inspect`, `make doctor`, `make capabilities`, and `make stats` use local runtime/provider evidence. Databricks authentication and workspace health are reported as not checked by those inventory commands; explicit Databricks operations perform remote validation when requested.

## Runtime state and recovery

Anvil stores a small validated runtime record under `$XDG_DATA_HOME/anvil/runtime.json`. Discovery checks the saved executable, installation metadata, Anvil-managed location, and current `PATH`, and validates the executable's current version before using cached state. PATH readiness is reported separately from whether the absolute executable works.

Backups record their scope. An Anvil-only rollback restores Anvil config and installation/runtime metadata while preserving the OpenCode executable, data, and state. Runtime update and migration snapshots retain the full runtime/config/data/state recovery path.

The offline lifecycle suite denies external network connections while exercising Anvil upgrade, reforge with an existing runtime, inspect, doctor, and capabilities. Loopback access remains available to the isolated OpenCode 2 fixture.

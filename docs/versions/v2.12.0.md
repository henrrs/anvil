# Anvil 2.12.0 — Editorial Intelligence & Local Environment Preservation

Anvil 2.12 refines the artifact-only communication skill and makes lifecycle operations preserve shared OpenCode configuration according to explicit ownership. The candidate adds no runtime requirement, new dependency, agent, or public Make target.

## What changed

- The `anvil-communication` skill now emphasizes comparison context, materiality, finding/insight/implication, content reduction, slide economy, semantic relationships, chart skepticism, direct annotation, whitespace, asymmetric composition, and meaningful motion. It is loaded for artifact work, not routine coding.
- The existing managed-config manifest now records Anvil-owned profile keys, agent names, plugin identity, and reference identity. Schema-1 manifests without the new optional ownership fields remain readable.
- OpenCode profile rebuilds preserve external plugins, MCP servers, user references, providers, custom agents, runtime preferences, and unknown configuration while updating Anvil-owned fields. Supported V1/V2 provider, plugin, MCP, and agent settings are merged across explicit runtime migrations.
- Snapshots contain Anvil-owned files, the shared profile, and CLI/TUI preferences. External files stay in place instead of being copied into each archive. Rollback stages prior Anvil state and merges current external files and shared settings; a user-owned path collision blocks before live replacement.
- Dry-run output states what is managed, what is merged or left untouched, and what a snapshot would contain. It does not print config values.
- The same-major migration window includes six prior minor releases, retaining supported Anvil 2.6.x source profiles.

## Compatibility and commands

```bash
git pull origin master
make test
make upgrade DRY_RUN=1
make upgrade
make doctor
```

OpenCode 1.x and 2.x remain supported. `make upgrade` preserves the exact validated runtime; runtime updates and major migrations remain separate commands. No memory, Databricks, task-state, or other user-data schema migration is required.

## Evaluation and known limits

Offline fixtures cover first use with a non-Anvil OpenCode profile, upgrades/reforge, plugin/MCP/profile merging, external package/proxy/certificate/shell files, scoped snapshots, and post-upgrade user changes through rollback. Eleven editorial-judgment fixtures cover context, materiality, compression, composition, charts, and motion. These fixtures are not a live-model quality result.

The repository contains no current Anvil presentation deck or GIF for a before/after semantic review. No live-model latency comparison was run. Shared JSONC values survive parsing and merge, but original comment formatting is not preserved when the profile is serialized. The candidate is **NOT RELEASE READY** until the real deck benchmark and live-model responsiveness evaluation are completed.

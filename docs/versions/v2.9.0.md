## Upgrade and compatibility

```bash
git pull origin master
make test
make upgrade DRY_RUN=1
make upgrade
make doctor
```

`make upgrade` preserves the exact validated OpenCode executable/version and existing data/state. **Network required: NO** for Anvil-only upgrade. Use `make update-runtime` only for an explicit same-major OpenCode update, or `make migrate-runtime OPENCODE_MAJOR=N` for an explicit major change. Existing commands, memory, Databricks and communication artifacts remain available.

No existing user task data needs migration. New state is optional schema-1 JSON under XDG_STATE_HOME/anvil/engineering; it is not durable memory and is outside config/runtime rollback snapshots. Versioned inventory ownership recognizes new skills/scripts without demanding them from older source profiles. The source migration window extends to three prior minors so the previously supported 2.6 source line remains upgradeable. [Migration details](../migrations/v2.8.0-to-v2.9.0.md).

Release recommendation: READY WITH KNOWN LIMITATIONS after the mandatory gates. Semantic extraction/design/diagnosis remain model-guided; external-effect idempotency remains the application's responsibility. Binary PPTX generation is unchanged and unavailable.

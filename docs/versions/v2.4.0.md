# Anvil 2.4.0 — Safe Lifecycle and Databricks Onboarding

## Release choice

Anvil 2.4.0 is a MINOR release. It adds backward-compatible user-facing capabilities for runtime quiescing, human command presentation, environment-aware authentication selection, and guided Databricks setup. Existing commands, OpenCode 1/2 runtime support, and provider state remain compatible.

## Safe Anvil upgrades

`make upgrade DRY_RUN=1` is read-only with respect to live Anvil/OpenCode state. It rehearses with the exact validated runtime, reports any matching OpenCode processes, and states that no processes were stopped and no files were changed.

A real `make upgrade` completes config/runtime/path/backup preflight before asking for confirmation or interrupting OpenCode. It identifies the exact validated executable, same-user process, and configured OpenCode data roots. It refuses to stop a runtime that is an ancestor of the upgrade. After the cancellable countdown it sends SIGTERM, waits up to the bounded grace period, uses SIGKILL only if needed, verifies quiescence, and creates the Anvil-only snapshot. Anvil does not restart the TUI; start OpenCode normally when ready.

Set `ANVIL_UPGRADE_COUNTDOWN_SECONDS` or `ANVIL_OPEN_CODE_GRACE_SECONDS` for a shorter or longer bounded interval. They are primarily useful for local administration and tests.

Network required for `make upgrade`: NO. Explicit runtime changes still use `make update-runtime` or `make migrate-runtime OPENCODE_MAJOR=N` and may require upstream release access.

## Human-first Databricks commands

`make databricks-setup`, `make doctor`, and `make capabilities` now default to concise human output. Setup reports provider readiness, selected profile, important warnings, and the next action without exposing internal executable paths. Use `make databricks-setup OUTPUT=json` for the full structured result and `make databricks-setup VERBOSE=1` for local provider diagnostics. `make capabilities FORMAT=json` remains the combined machine-readable runtime/Databricks report.

## Authentication orchestration

Setup detects local terminal, VS Code local/remote, SSH, container, WSL, and headless contexts before selecting a supported authentication path. It reuses validated profiles, runs official Databricks CLI OAuth U2M from a local interactive terminal, and may use Microsoft Azure CLI device-code login plus Databricks SDK `azure-cli` authentication for Azure workspaces in remote environments. Remote AWS/GCP contexts are directed to a supported Databricks profile or the official VS Code extension instead of assuming a browser callback can reach the remote process.

CLI installation is attempted only by explicit `make databricks-setup`; internal absolute paths remain Anvil implementation details. If CLI installation is blocked, the SDK can still satisfy supported operations with an existing compatible auth profile or supported Azure CLI session. VS Code stays an assisted integration; Anvil does not automate its UI or inspect private credential stores.

## Compatibility and validation

Anvil 2.4.0 retains the OpenCode 1.x and 2.x runtime matrix. Upgrade safety, presentation, and Databricks setup are independent of OpenCode major. Mandatory regression tests use local CLI/runtime/Azure doubles and do not contact external systems.

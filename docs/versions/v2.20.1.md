## What changed

The shared managed instructions now state that an explicit sequence of dependent phases is sufficient reason to load `anvil-engineering`, even when the task is small or contained in one repository. They give validation, dependency resolution, filesystem activation/rollback, and CLI integration as a concrete example. This makes the existing lazy trigger easier for the model to recognize without making the skill load for unrelated work.

No skill content, task-state model, OpenCode agent configuration, plugin, runtime policy, Analytics behavior, or provider behavior changed. `config/managed-inventory.json` carries the new release and checksums for the managed `AGENTS.md` and `VERSION` artifacts.

## Installation and migration

Run `make inspect`, then `make upgrade DRY_RUN=1` and review the plan before `make upgrade`. `make reforge` also regenerates the managed profile from this release. Both paths preserve the exact validated OpenCode executable and user-owned configuration. There is no data or persistent-schema migration; the migration guide is [here](../migrations/v2.20.0-to-v2.20.1.md).

The inherited Analytics capability remains unchanged: `config/analytics-requirements.lock`, Python 3.11+, the canonical Analytics session, Unity Catalog and warehouse operations, and the existing 1366×768 visual case are unaffected.

# Anvil 2.10.0 — Adaptive Engineering Execution

Anvil 2.10 keeps Long-Horizon Engineering's requirements, architecture, work continuity, stale-state detection, crash-safe resume, and completion gates. Adaptive Engineering Execution decides how much to activate for the **current task**. A local fix remains direct even inside a large project with an active Work Model. There is no required user mode, second agent, model router, OpenCode upgrade, or Python package.

## What changed

- Replaced repository-size/request-length activation thresholds with explicit task-risk signals and model judgment. Project counts and long text are context hints, not activation gates.
- Reduced the always-loaded `config/AGENTS.md` from 3,930 to 3,338 bytes while retaining safety and recovery invariants.
- Kept requirements, architecture and work slices dormant for unrelated local work; skill guidance now supports task-local escalation and de-escalation.
- Made architecture evidence selective by declared paths/patterns. `checkpoint --milestone ID --revision N` evaluates only missing or invalid invariants for a completed milestone and reuses still-valid evidence. An unscoped checkpoint remains a full audit.
- Preserved atomic state schema 1, stale checks, corruption recovery, requirement gates, interruption behavior, and both OpenCode profile generations.
- Retained upgrade/reforge/rollback lifecycle semantics and extended the source migration window to four prior Anvil minor releases so 2.6.x remains supported.

## Evaluation

The offline adaptive route rubric matched 18/18 task cases. Against the 2.9 deterministic activation rule, low-risk cases falsely routed to long-horizon fell from 8 to 0, and explicit expansion cases missed fell from 8 to 0. Those are helper/rubric results, not live model behavior.

Three ingestion replays retained 12/12 required requirements and all four architecture invariants while mechanical architecture evaluations fell from 20 to 4 per replay. Three unrelated scheduler replays retained 7/7 requirements and both invariants while checks fell from 8 to 2. Replay state writes stayed 7 and 6, and verification commands stayed 4 and 3. These are deterministic protocol metrics; tool usage, model tokens, source files read, and real task latency were not measured because OpenCode/live model execution was unavailable.

See the [full evaluation](../engineering-evaluation.md), [adaptive policy](../adaptive-engineering.md), and [migration guide](../migrations/v2.9.0-to-v2.10.0.md). Recommendation: **READY WITH KNOWN LIMITATIONS**; real-model behavior remains unmeasured.

## Upgrade and compatibility

```bash
git pull origin master
make test
make upgrade DRY_RUN=1
make upgrade
make doctor
```

`make upgrade` preserves the exact validated OpenCode executable/version and existing user/task data. Anvil 2.10 supports the same OpenCode 1/2 profile generations; runtime migration is not required. Existing task-state schema 1 remains readable. The `engineering.py assess` recommendation now returns `DIRECT` or `EXPAND`; `EXPAND` does not itself create state or require all models. No durable memory, Databricks, or communication-artifact migration is required.

Network required: **NO** for an Anvil-only upgrade. Use `make update-runtime` only for an explicitly requested same-major OpenCode update; use `make migrate-runtime OPENCODE_MAJOR=N` only for an explicitly requested major migration.

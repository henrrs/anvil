# Anvil 0.1.0 — V1

## Overview

Anvil V1 established a small, model-agnostic global harness for OpenCode. OpenCode remained responsible for models, providers, authentication, sessions, tools, and runtime behavior. Anvil supplied one primary agent, concise instructions, a fixed skill set, explicit memory commands, and a user-managed install/backup lifecycle.

This history is derived from the V1 repository at the V2 upgrade baseline. It describes implemented behavior, not proposals from earlier design notes.

## Goals and architecture

- One Anvil primary agent with no model or variant pinning.
- The provider's native system prompt remained active; Anvil added a compact global `AGENTS.md`.
- OpenCode's built-in primary and subagent choices were disabled in the V1 config. The `task` tool was denied.
- Global MCP and plugins were empty by default.
- Five lazy skills covered memory, Spark performance, Delta Lake, Databricks, and data ingestion.
- Memory was explicit-only Markdown under `$XDG_DATA_HOME/anvil/memory/`, with `/remember` writes and `/recall` reads.
- Memory recorded type, scope, tags, source, confidence, and dates. Duplicate-aware updates used atomic file replacement.
- `make reforge` staged an official OpenCode release, validated it, created a checksummed backup, and rebuilt the global Anvil config.
- `make inspect`, `make test`, and `make doctor` provided environment inspection and lifecycle verification.
- `make rollback` restored the saved config and installer directory and retained Anvil memory.

## OpenCode baseline and lifecycle

V1 used OpenCode 1's singular `agent`, `permission`, and `plugin` configuration keys. Its reforge path did not provide a dedicated V1-to-V2 migration rehearsal, and its backups did not yet archive OpenCode data and state as part of a runtime-generation rollback.

The V1 install recorded the selected OpenCode version but did not record an Anvil release version in `installation.json`. For older installations, V2 therefore reports the former Anvil release as unrecorded rather than inferring a precise patch version.

## Commands and limitations

V1 provided `/remember` and `/recall`. It did not provide `/distill`, a source registry, an OpenCode memory search tool, native References, `make upgrade`, `make stats`, or a V2-native plugin.

V1 intentionally had no model router, multi-agent orchestration, automatic memory extraction, vector database, or telemetry database.

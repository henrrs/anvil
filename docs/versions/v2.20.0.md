## What changed

- OpenCode 2's documented native compaction hook now optionally receives a bounded checkpoint for the single active Anvil engineering task associated with that session's repository. The checkpoint is reconstructed from the existing Requirements, Architecture, and Work state; it does not include conversation transcripts, does not execute work, and marks changed repository evidence stale. Hook setup and packet lookup fail soft so native compaction continues if the installed V2 build or local helper does not support this path.
- OpenCode 1 continues to use Anvil's existing explicit `resume` workflow; the V2-only hook is not added to the V1 plugin.
- Added a lazy engineering quality reference for codebase comprehension, contract and impact checks, root-cause debugging, maintainable refactoring, independent regression tests, risk-based validation, API/dependency review, security, and evidence-based final review.
- Added a deterministic retry-policy fixture with a deliberately defective implementation and independent acceptance checks, plus `make eval-engineering`. Added `make eval-engineering-model MODEL=... OPENCODE=...` as an explicit, isolated live evaluation interface; it was not run for this release.
- Made the Databricks CLI minimum-version fixture hermetic against host-installed CLI candidates. Production discovery is unchanged.

## Installation and migration

Run `make upgrade DRY_RUN=1`, inspect the local plan, then run `make upgrade`. Existing OpenCode executables, profiles, provider configuration, data, and task-state schema remain unchanged. The same-major migration window is extended to fourteen prior minor releases to retain the previously supported 2.6.x Anvil source line. After upgrade, `make test` runs the offline integration suite; `make eval-engineering` runs deterministic fixture replays.

There is no data migration. The compaction feature only reads active task state. If there is no unique active task for the repository, no checkpoint is added. If state is absent, ambiguous, corrupt, stale beyond a usable packet, or the helper times out, native OpenCode compaction proceeds without Anvil context. On V1, use the documented `engineering.py resume` command after compaction.

## Preserved product/runtime context

The release leaves the Analytics Workspace, its canonical Analytics session, Unity Catalog provider, and pinned `config/analytics-requirements.lock` unchanged. The supported local prerequisite remains Python 3.11+. Existing Analytics visual certification includes 1366×768. These inherited capabilities are unchanged; this release adds no Analytics or warehouse behavior.

## Verification boundary

Offline source and integration tests verify packet bounds, state selection, stale handling, and that the V1 plugin does not register the V2 hook. The OpenCode 2 API is documented, but live hook execution has not been exercised in an OpenCode 2 process during this release. Live model correctness, compaction recovery rate, token savings, latency, provider cost, and real project outcomes are **NOT EXECUTED / NOT MEASURED**.

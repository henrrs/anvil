# Anvil 2.14.0 — Analytical Intelligence Architecture Realignment

**Status:** Candidate; **NOT READY** pending model-level quality, cost/latency, and product-level analytical evaluation.

## Overview

Anvil 2.14 makes the existing bounded analysis package a reusable renderer-independent capability. It strengthens semantic context for observation grain and candidate entities, introduces a clean dependency direction from analysis to communication consumers, and reuses one deterministic implementation for distribution/change arithmetic.

## What changed

- Added bounded task-level semantic candidates for observation count, categorical entity keys, temporal repetition, unique/composite row grain, dimensions, measures, metric templates, questions and quality risks. These remain uncertain candidates; they are not a semantic catalog.
- Added composite-key distinct counts, repeated entity-period aggregation for cohort comparisons, retained/added/removed population evidence, direction-aware breadth, and additive count/sum contribution shares.
- Added category-composition comparison with category shares, total population-share movement, and optional per-category/overall metrics. It surfaces mix shifts but does not claim causality or perform exact mean/rate decomposition.
- Added source-profile reuse during execution with exact path/hash/row-count/completeness checks and per-run observability metadata.
- Added result checks for execution/plan correspondence, row/entity claims, three-point trend language, cohort/like-for-like claims, breadth thresholds, coverage shifts and causal classification.
- Moved the adapter to `scripts/communication/analysis_adapter.py`; analysis no longer imports communication/artifact code. Shared deterministic distributions and deltas are in `scripts/analysis/statistics.py`.
- Expanded the lazy communication skill for direct analysis and artifact reuse. No new always-loaded prompt context, agent, dependency, model route, service, runtime feature or durable state was added. The opt-in `eval-analytical*` Make targets invoke the separate evaluation package only when explicitly requested.

The helper supports deterministic FAST/STANDARD/DEEP plan budgets. It does not implement autonomous multi-stage hypothesis escalation, exact composition decomposition, general anomaly detection, or automatic executive narrative generation. Existing Markdown and SVG outputs remain supported; binary PPTX/DOCX/PDF rendering is not available.

## Compatibility and migration

OpenCode 1.x and 2.x remain supported. No runtime/profile migration, memory/data migration, package dependency, external service, or user configuration change is needed. Anvil 2.14 is installed through the existing managed file manifest and lifecycle transaction. The supported same-major source window extends eight prior minor releases, retaining the previously supported 2.6.x line. `make upgrade` remains Anvil-only and preserves the validated runtime. **Network required:** No for `make upgrade`; yes only for separate runtime update/migration operations.

Follow the [2.13-to-2.14 migration guide](../migrations/v2.13.0-to-v2.14.0.md). `make upgrade` installs Anvil while preserving the exact validated OpenCode runtime; `make update-runtime` is a separate explicit command. **Network required:** No for Anvil upgrade; yes only for the separate runtime update/migration. See the [analytical guide](../analytical-intelligence.md), [architecture assessment](../analytical-intelligence-realignment-v2.14.0.md), [engineering report](../analytical-intelligence-report-v2.14.0.md), and [ADR-0022](../decisions/ADR-0022-analytical-intelligence-boundary-and-semantics.md).

## Evaluation and release recommendation

The analytical evaluation harness uses two versioned synthetic datasets and measures exact L1 facts and separate L2 semantic candidates; model-backed blind discovery and L3–L5 require an explicit provider run and structured human review. See the [analytical evaluation guide](../analytical-intelligence-evaluation.md) for fixture design, execution, private-case policy, metric definitions and immutable baseline workflow. Deterministic passes do not establish model quality or presentation fidelity.

The immutable baseline is [`evals/analytical/baselines/anvil-2.14.0-deterministic-v1.json`](../../evals/analytical/baselines/anvil-2.14.0-deterministic-v1.json), frozen from run `20261031T153737Z-503d82c7` (SHA-256 `e647ed84203c6f20d93ae03c9b07a8420b68cb1183e65091487b23ccc8b3f753`). The full offline `make test` suite passed. After freezing, model-runner executable discovery was hardened to use Anvil's validated managed runtime even outside `PATH`, and FAST classification now requires at least three timing repetitions. The trap suite also gained a new `stable-average-tails-v2.csv` because review found the original snapshot did not keep its mean stable; the prior file remains preserved. These evaluator-only changes do not alter the frozen main-fixture L1/L2 or five-repetition timing results; the baseline contains no model results. A live-model attempt was blocked because this environment has no OpenCode executable; therefore discovery, claim calibration, model latency/tokens, and communication fidelity remain unmeasured. The candidate is **NOT READY**.

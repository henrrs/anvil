# Anvil 2.16.0 — Analytics Workspace

## Overview

Anvil 2.16.0 adds a default-installed global Analytics Workspace for cached Unity Catalog navigation, lazy table details, bounded previews, read-only SQL, contextual Ask Anvil and explicit local materialization. It is a MINOR release and retains OpenCode 1.x and 2.x runtime independence.

The automatic same-major source window covers ten prior minor releases, retaining the previously supported Anvil 2.6.x source line.

The shared base agent remains within its established context budget:

| Release | `AGENTS.md` bytes | Approximate tokens |
|---|---:|---:|
| Anvil 2.16.0 | 3,511 | 878 |

## Architecture and user data

The feature composes the shared Anvil Databricks capability, one OpenCode runtime, an isolated canonical Analytics session and the existing Anvil memory/skills/tools. A loopback BFF serves the same-origin UI. SQLite WAL stores control/context state; optional DuckDB executes a conservative local SQL subset; Parquet holds user-selected local snapshots. Analytics data is outside managed config and lifecycle backups.

## Compatibility and migration

`make upgrade` includes Analytics for existing supported installs and preserves the exact validated OpenCode executable. It configures a user systemd service where available, or leaves a foreground fallback. OpenCode 1 and 2 have separate plugin implementations; both call the same bounded Analytics tools. No OpenCode major change is required. `make upgrade DRY_RUN=1` remains local and read-only.

Use `make upgrade DRY_RUN=1`, `make upgrade`, `make doctor`, and `make analytics-status`. Then start with `make analytics` and open `http://anvil.localhost:8765`. See the [migration guide](../migrations/v2.15.0-to-v2.16.0.md), [user guide](../analytics-workspace.md), [architecture](../analytics-workspace-architecture.md), [operations](../analytics-workspace-operations.md), and [data-plane design](../analytics-workspace-data-plane.md).

The [engineering report](../analytics-workspace-report-v2.16.0.md) records acceptance evidence and the live integration checks that remain environment-specific.

## Limits

DuckDB and PyArrow are optional Python dependencies, so local SQL and materialization can report degraded independently of the remote catalog/SQL capability. Databricks system-table lineage depends on workspace permissions and the documented coverage of that table. Host-side WSL browser reachability is `NOT_CHECKED` by local certification. Live provider/model quality require separate environment-specific validation. These checks do not validate a live Databricks workspace. Network required for the local Anvil upgrade: **NO**.

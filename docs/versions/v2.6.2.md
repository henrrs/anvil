# Anvil 2.6.2

Anvil 2.6.2 hardens first use, partial-install reporting, command failure presentation, and Databricks SDK bootstrap. It retains the existing OpenCode 1 and 2 adapters and schema-3 Databricks readiness contract.

## Lifecycle and public commands

- Added a shared lifecycle evaluator for repository-only, partial, installed, ready, degraded, and corrupted states.
- Added the [public Make command contract matrix](../command-contracts.md), covering preconditions, side effects, network/runtime behavior, user-facing outcomes, and exit semantics.
- `make inspect` and `make doctor` classify partial and corrupted installation states. Upgrade and runtime lifecycle commands use shared precondition checks. A first-use rollback explains that no snapshot exists and points to reforge.
- Doctor preserves Databricks status diagnostics and no longer labels a missing readiness record stale when no profile is configured.
- Python public command failures receive a generic safe summary by default; `DEBUG=1` adds redacted diagnostic frames.

## Databricks SDK bootstrap and diagnostics

- SDK setup checks the Python executable, virtual environment, and pip before installation. Missing pip is a structured blocker with a direct remediation; a healthy CLI can remain the primary provider.
- SDK discovery, installation and persistence preserve `<Anvil data>/venv/bin/python` as the invocation path, including when it is a symlink to the base interpreter.
- The SDK worker constructs `Config` from the selected Anvil profile, explicit Anvil config file, and bounded timeouts, then passes that object to `WorkspaceClient`.
- Safe SDK failure phase, operation, normalized exception category/status, retryability, and failure scope reach the human setup/doctor result without forwarding arbitrary exception messages or response data.
- No readiness transition, provider selection policy, credential storage, or schema-3 persistence rule changed.

## Runtime compatibility

Anvil 2.6.2 continues to support OpenCode 1.x from `1.18.18` and OpenCode 2.x from `2.0.0`. `make upgrade` remains Anvil-only and preserves the exact validated runtime; runtime updates and major migrations remain explicit.

The offline release tests use isolated HOME/XDG roots and local fixtures. They cover fresh command matrices before and after reforge, partial/corrupted states, offline blockers, missing pip, venv symlink identity, explicit SDK configuration and safe diagnostics through the worker process boundary. No live OpenCode release, Databricks workspace, Azure account, or external service was used.

`make update-runtime` remains the explicit same-major runtime update operation. `make migrate-runtime OPENCODE_MAJOR=2` remains the explicit major migration operation. Network required: those runtime operations, first-install runtime provisioning, and explicitly requested Databricks provider setup/workspace validation may access their official release/provider endpoints.

# Anvil 2.13.0 — Intent Compilation & Analytical Intelligence

**Status:** Candidate; **NOT RELEASE READY** pending live-model quality and responsiveness evaluation.

## Overview

Anvil 2.13 adds task-local intent compilation and bounded analytical intelligence to the existing single Anvil agent and lazy `anvil-communication` skill. The original request remains authoritative. Data is profiled and calculated deterministically; semantic interpretation, question choice, hypothesis, materiality judgment, and narrative remain model reasoning. Simple non-data tasks keep their direct path.

## Architecture assessment and implementation

The repository assessment is recorded in [Intent Compilation and Analytical Intelligence — Architecture Assessment](../intent-analytical-architecture-assessment.md), and the boundary decision is [ADR-0021](../decisions/ADR-0021-intent-compilation-and-analytical-intelligence.md).

Added the stateless `scripts/analysis/` package for:

- exact-request `TaskBrief` validation, with separate explicit and reasoned-derived requirements;
- source-hash-bound plans, semantic field confidence, supported depth and operation budgets;
- deterministic profiles for explicitly named CSV, TSV, flat JSON row arrays, and JSON Lines;
- reusable bounded calculations for counts, numeric summaries, rank/share/concentration, period changes, distributions, trends, volatility, coverage, ratios, cohorts, and correlations;
- typed, provenance-linked evidence and findings, Pareto materiality tiers across named dimensions, and an artifact-independent result contract;
- a narrow adapter into the existing communication evidence/finding contracts.

`scripts/analyze.py` exposes local profile, plan execution, contract validation, and artifact adaptation. It has no model call, network request, external package, persistent store, or output-file write. `make capabilities` reports its supported inputs and limits. No additional Make target or OpenCode skill permission was introduced.

## Intent, analysis, and evidence

The existing lazy communication skill now covers data analysis as well as evidence-backed artifact creation. It keeps short tasks on the direct path; compiles structured intent for analytical tasks; asks only for material unresolved decisions; profiles named data; assigns semantic confidence; chooses a bounded question set and FAST/STANDARD/DEEP depth; considers population change, distribution, coverage, trend, and competing explanations when relevant; and builds narrative only after findings.

Each executed plan binds to the profile SHA-256. Changed sources, missing columns, unsafe paths, unsupported shapes/units, and exceeded budgets stop with an actionable error. The operation cap is 4/12/20 for FAST/STANDARD/DEEP; inputs are limited to 32 MiB, 100,000 rows, 200 columns, and 250,000 profile cells; group expansion is capped at 100 groups per operation, two dimensions, and a 5 MiB total result. Large profiles explicitly label prefix statistics; execution never silently uses a partial prefix.

Findings distinguish OBSERVED, DERIVED, INTERPRETED, HYPOTHESIS, and UNKNOWN. Non-unknown findings need evidence IDs. Materiality records magnitude, breadth, persistence, decision relevance, confidence, exception severity, novelty, and a rationale. Ranking is a deterministic Pareto order with no opaque weighted score. The communication adapter preserves evidence data and hypothesis labels without selecting layout or recalculating measures.

## Compatibility and local configuration preservation

OpenCode 1.x and 2.x remain supported. No runtime, profile, provider, model, user-data, memory, or Databricks state migration is required. The helper is added through the existing Anvil-owned managed-file manifest and lifecycle transaction; user-owned and machine-local config remain outside Anvil ownership. The same-major source window extends to seven prior minor releases to retain the supported 2.6.x source line. `make upgrade` remains Anvil-only and preserves the exact validated OpenCode executable; `make update-runtime` remains a separate explicit, network-required operation. **Network required:** No for `make upgrade`; yes for the separate runtime update.

## Tests and evaluation

`tests/analysis.py` checks request provenance, requirements, formats, profile limits, deterministic arithmetic and distributions, percentage/percentage-point distinctions, cohort composition, like-for-like comparisons, temporal evidence thresholds, units, coverage, correlation language, evidence references, Pareto materiality, summary/presentation adaptation, and an unrelated helpdesk dataset. A separate three-period operations fixture tests the case where aggregate latency improves while an edge segment and like-for-like cohort deteriorate, alongside volume, coverage, a stable metric, population movement, and an outlier. In the final full-suite run, a local 10,000-row end-to-end profile and execution measured FAST (4 operations) at **151.3 ms**, STANDARD (12) at **189.6 ms**, and DEEP (20) at **235.7 ms**, with two source scans per run. These are single-run measurements, not a general latency guarantee. The deterministic helper made zero model/tool calls and used zero prompt tokens; the real agent's model calls, tool calls, and token use were not measured.

The earlier 2.12 baseline `make test` suite passed before implementation, and the final candidate `make test` suite also passed. The prior artifact raw-table comparison API did not exist, so a like-for-like raw-table baseline latency and coverage score is unavailable. Offline fixtures validate deterministic calculations; semantic misses, unsupported claims generated by a live model, model/tool-call counts, token usage, live task latency, and real user-data performance remain **unmeasured**. See the [engineering report](../intent-analytical-report-v2.13.0.md) for the complete evaluation.

## Release recommendation

**NOT RELEASE READY.** The deterministic implementation and lifecycle boundary have offline coverage, but the specified live-model intent/question/claim-fidelity evaluation and responsiveness/token measurements were unavailable. A passing offline suite must not be interpreted as proof of semantic task quality. See the [analytical-intelligence guide](../analytical-intelligence.md) and final [engineering report](../intent-analytical-report-v2.13.0.md).

# Anvil 2.6.0

Anvil 2.6.0 makes Databricks readiness a validated runtime contract. It preserves the independent OpenCode 1 and OpenCode 2 adapters, the CLI/SDK provider boundary, existing Anvil-owned authentication, and the Anvil-only upgrade lifecycle.

## Databricks readiness

Setup and doctor now use the same production provider route as a later Anvil session. A new profile can report `READY` only after Anvil validates the current identity for the configured workspace and successfully lists both clusters and SQL warehouses. Empty lists are valid. A running cluster, SQL warehouse, or system-table permission is not needed for setup.

Provider state schema 3 records the readiness stage, validation time, provider and probe, and per-capability result counts without credentials. State writes use a private temporary file, atomic replacement, and directory sync. Legacy profile/provider state is read through the existing lazy migration path; saved old readiness is revalidated before doctor reports it healthy.

The resolver permits fallback for provider-specific timeouts, malformed provider output, and unavailable providers. It stops on shared authentication/network problems, permission denials, invalid arguments, and unknown execution failures. Diagnostics keep the root blocker and provider-resolution reasoning.

`make doctor` revalidates a configured Databricks profile using read-only identity, clusters-list, and warehouses-list calls. With no Anvil profile it remains local and reports `NOT_CONFIGURED`. `make capabilities` stays local and separates Supported, Available, and Verified; local cached validation becomes stale after 15 minutes.

## Runtime compatibility

The release preserves OpenCode 1.x and OpenCode 2.x runtime profiles and does not require OpenCode 2. Runtime migration remains explicit through `make migrate-runtime OPENCODE_MAJOR=N`; `make update-runtime` performs a same-major update, and `make upgrade` preserves the exact validated OpenCode executable/version.

## Version choice and verification

This is a MINOR release because it adds a public readiness contract and schema-3 validation semantics while keeping commands backward compatible and old state lazily readable.

`make test` covers the offline readiness state machine, false-READY prevention, clean-process revalidation, process timeout and child cleanup, empty core lists, selective provider fallback, shared-failure propagation, partial permissions, documented CLI grammar, OpenCode 1/2, and existing lifecycle/FinOps regressions. No live Databricks workspace, cloud login, or external service was used. The exact validated OpenCode executable remains unchanged by Anvil upgrade, and network required for `make upgrade` remains `NO`.
